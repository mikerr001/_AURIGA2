How Auriga should behave

Trust is earned in the details.

Assistive software has to be useful when it works—and clear when it cannot.

⌂

Local-first by design

Prioritise processing on the phone and avoid requiring an account or remote server for core features where practical.

!

Fail honestly

If the detector, camera, or metric scale is unavailable, report that state. Never invent a distance or present a guess as a hazard warning.

◉

Accessible controls

Large targets, clear focus, screen-reader labels, concise speech, and explicit microphone activation are part of the product—not polish for later.

Straight answers

What is ready—and what is not.

We prefer a clear limitation to a polished overpromise.

Is the Android app the same as the web demo?

No. The Android app uses native Android activities and camera APIs. The browser demo is a separate prototype; the website illustration above is not a live camera feed.

Does Auriga provide reliable distance measurements?

Not as a validated mobility capability. Metric outputs must remain disabled whenever the detector, visual tracking, or scale confidence is not validated.

Does it always listen to my microphone?

The intended interaction is explicit voice activation. The app should request microphone access when you activate voice, show listening status, and release audio resources when listening ends.

How do I get an APK?

Open the GitHub Actions builds. Use an APK only when the corresponding workflow completes successfully and publishes an artifact.

Help improve Auriga
